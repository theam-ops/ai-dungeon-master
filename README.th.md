เกม RPG แนว D&D ที่มี Claude Opus 5 เป็นผู้คุมเกม (Dungeon Master) มันเล่าเรื่อง สวมบทบาท
NPC ทุกตัว และตัดสินกฎให้ ส่วนงานที่โมเดลภาษาทำได้ไม่ดี — ทอยลูกเต๋า คำนวณเลข จำว่าคุณ

เล่นผ่านเบราว์เซอร์ได้ทุกอุปกรณ์ จะเล่นคนเดียวหรือชวนเพื่อนมาลงแคมเปญเดียวกันก็ได้
รองรับ **ภาษาไทยและภาษาอังกฤษ** ถ้าเครดิตของ Claude หมดกลางเกม ระบบจะสลับไปใช้ AI ตัวอื่น
ให้เองอัตโนมัติ และยังมีตัวเล่นผ่านเทอร์มินัล (`dnd.py`) ที่ใช้ DM และกฎชุดเดียวกัน

## เริ่มเล่นเร็วที่สุด — วางไอคอนไว้บนเดสก์ท็อป (Windows)

เปิดโฟลเดอร์ `tools` แล้วดับเบิลคลิก **Create shortcut.cmd** จะได้ไอคอนลูกเต๋า d20 ชื่อ
*AI Dungeon Master* บนเดสก์ท็อป ดับเบิลคลิกเพื่อเล่นได้เลย ครั้งแรกมันจะติดตั้งของที่ขาด
ให้เอง แล้วเปิดเซิร์ฟเวอร์กับเบราว์เซอร์ ปิดหน้าต่างที่ค้างไว้เมื่อต้องการหยุดเกม

ถ้าย้ายโฟลเดอร์ไปที่อื่น ให้รัน **Create shortcut.cmd** ใหม่อีกครั้ง เพราะช็อตคัตจำตำแหน่ง
แบบเต็มไว้

ถ้าไม่อยากสร้างช็อตคัต ดับเบิลคลิก **Play.cmd** ในโฟลเดอร์นี้ หรือสั่ง:

```bash
python launch.py
```

`launch.py` รับ `--port 9000` ถ้าพอร์ต 8000 ไม่ว่าง (แต่ปกติมันหาพอร์ตว่างเองอยู่แล้ว)
และ `--no-browser` ถ้าอยากเปิดแท็บเอง

คุณยังต้องมี AI สักตัวมาเป็น DM — ถ้ายังไม่ได้ตั้งค่า เกมจะบอกและพาไปยังตัวเลือกที่ฟรี
ดูหัวข้อ **เล่นฟรีโดยไม่ต้องมี API key** ด้านล่าง หรือใช้ Claude Pro ผ่าน Claude Code

## เริ่มเล่นแบบทำเอง (ทุกระบบปฏิบัติการ)

```bash
pip install -r requirements.txt
```

ตั้งค่า Anthropic API key (เอาจาก console.anthropic.com):

```bash
setx ANTHROPIC_API_KEY "sk-ant-..."
```

หลังใช้ `setx` ต้องปิดแล้วเปิดเทอร์มินัลใหม่ — หรือจะตั้งเฉพาะรอบนี้ด้วย
`$env:ANTHROPIC_API_KEY = "sk-ant-..."` ใน PowerShell ก็ได้

จากนั้น:

```bash
python -m uvicorn server:app --reload
```

เปิด **http://localhost:8000** สุ่มตัวละคร แล้วเล่นได้เลย

## เล่นจากมือถือ

**ทางเลือก ก — ทำอุโมงค์ (tunnel): ฟรี ทันที ไม่ต้องสมัคร และ Claude Pro ยังเป็น DM ได้**
เครื่องคุณยังรันเกมอยู่ แต่ได้ URL แบบ https สาธารณะมาให้:

```bash
python launch.py --share --password "รหัสที่รู้กันเฉพาะโต๊ะเรา"
```

ครั้งแรกมันจะดาวน์โหลด `cloudflared` (ราว 20MB ครั้งเดียว เก็บไว้ที่ `tools/bin/`)
แล้วเปิดเกมพร้อมพิมพ์ลิงก์แบบ `https://….trycloudflare.com` ออกมา ทุกคนที่เปิดลิงก์
จะเจอหน้าใส่รหัสผ่านก่อน

คำสั่งนี้ **ปฏิเสธที่จะแชร์ถ้าไม่ตั้งรหัสผ่าน** — ลิงก์สาธารณะที่ไม่มีรหัสผ่านก็เหมือน
เปิดบิลค้างไว้ให้คนทั้งอินเทอร์เน็ตใช้ AI ที่คุณจ่ายเงิน ลิงก์นี้จะตายเมื่อปิดหน้าต่าง
และเปลี่ยนใหม่ทุกครั้ง เหมาะกับ "คืนนี้เรานัดเล่นกัน" แต่ใช้เป็นที่อยู่ถาวรไม่ได้ —
อันนั้นเป็นหน้าที่ของทางเลือก ข

นี่เป็นทางเดียวที่ **Claude Pro ของคุณยังเป็น DM ได้** เพราะเกมยังรันอยู่บนเครื่องคุณ

**ทางเลือก ข — ดีพลอยขึ้นโฮสต์ (ใช้ได้แม้ปิดคอม)** ในรีโปมี `Dockerfile` และ
`render.yaml` อยู่แล้ว จึงใช้ได้กับโฮสต์ที่รันคอนเทนเนอร์ทุกเจ้า — Render, Railway,
Fly.io, Koyeb ถ้าใช้ Render: push โฟลเดอร์นี้ขึ้น GitHub สร้าง Blueprint จาก
`render.yaml` แล้วตั้ง `ANTHROPIC_API_KEY` กับ `APP_PASSWORD` ในหน้าแดชบอร์ด

> **ฟรีแปลว่าใช้แล้วทิ้ง** แพลนฟรีไม่มีดิสก์ถาวร และเครื่องจะหลับเมื่อไม่มีคนเข้าราว
> 15 นาที ดังนั้นแคมเปญ ตัวละคร รูปที่อัปโหลด และเอกสารที่นำเข้า จะหายทั้งตอนดีพลอยใหม่
> *และ* ตอนเครื่องหลับ ใช้ปุ่ม **Export** เก็บสิ่งที่อยากรักษาไว้ ไฟล์ `.zip` จะพารูปและ
> เอกสารไปด้วย และการเข้าครั้งแรกหลังเครื่องหลับจะใช้เวลาเกือบหนึ่งนาที

**ทางเลือก ค — เครื่อง Oracle Always Free** เป็นโฮสต์ฟรีจริงเจ้าเดียวที่มีดิสก์ไม่หาย
และแรงพอจะรัน Claude Code ได้ — แปลว่า Claude Pro เป็น DM บนเครื่องที่เปิดตลอดเวลาได้
ซึ่งไม่มีโฮสต์เจ้าอื่นทำได้ สคริปต์ `tools/oracle-setup.sh` จะติดตั้งเกม Claude Code และ
cloudflared บน Ubuntu ARM เครื่องใหม่ แล้วลงทะเบียนเป็น systemd service ให้ ต้องคัดลอก
รีโปขึ้นเครื่องก่อน (เพราะรีโปเป็นแบบส่วนตัว เครื่องนั้น clone เองไม่ได้) แล้วค่อยรัน
สคริปต์และทำตามสองขั้นตอนที่มันพิมพ์บอก

> **Oracle ยึดเครื่องที่ดูเหมือนไม่ได้ใช้งาน** — ถ้า CPU เน็ตเวิร์ก *และ* หน่วยความจำ
> ต่ำกว่า 20% ที่เปอร์เซ็นไทล์ที่ 95 ตลอด 7 วัน เซิร์ฟเวอร์เกมที่เล่นสัปดาห์ละไม่กี่คืน
> เข้าข่ายเต็ม ๆ วิธีแก้คืออัปเกรดบัญชีเป็น Pay As You Go ซึ่งได้รับการยกเว้น และทรัพยากร
> Always Free ยังฟรีเหมือนเดิม ควรทำก่อนย้ายแคมเปญขึ้นไป นอกจากนี้เครื่องแบบ ARM มักถูก
> ปฏิเสธเพราะเต็มตอนสมัคร — เตรียมใจลองใหม่หลายรอบ

> **ห้ามใช้ Vercel, Netlify หรือโฮสต์แบบ serverless** เพราะให้ฟังก์ชันมาพร้อมระบบไฟล์
> ที่เขียนไม่ได้และ `/tmp` ที่หายตลอด อีกทั้งกระจายทราฟฟิกไปหลายอินสแตนซ์ที่ไม่แชร์
> ที่เก็บข้อมูลกัน — `campaign.db` จึงอยู่ไม่ได้ รูปที่อัปโหลดอยู่ไม่ได้ และฟีดสดจะพังทันที
> เพราะมันคือการเชื่อมต่อ SSE ยาว ๆ หนึ่งเส้นต่อหนึ่งเบราว์เซอร์ ที่ผูกกับชุด subscriber
> ในหน่วยความจำ ถ้าอยู่คนละอินสแตนซ์ เสียงเล่าเรื่องของ DM จะไปไม่ถึงผู้เล่นคนอื่นเลย
> แอปนี้ต้องการคอนเทนเนอร์ที่รันค้างไว้ ถ้าจะย้ายไป serverless ต้องเปลี่ยนไปใช้ฐานข้อมูล
> ภายนอก ที่เก็บไฟล์ภายนอก และเขียนระบบสตรีมเหตุการณ์ใหม่ทั้งหมด

> **Claude Pro ตามไปด้วยไม่ได้** แบ็กเอนด์ "Claude Pro/Max (this machine)" สั่งงาน
> Claude Code ที่ติดตั้งอยู่บนเครื่องนั้น ๆ ซึ่งในดาต้าเซ็นเตอร์ไม่มี สำเนาที่ดีพลอย
> ขึ้นโฮสต์จึงต้องใช้ API key — คีย์ Gemini แบบฟรีเป็นทางที่ถูกที่สุด

การรันทั้งสองแบบพร้อมกันก็สมเหตุสมผล และเป็นเหตุผลที่มีสองทางเลือก: อินสแตนซ์ที่ดีพลอย
ไว้ให้โต๊ะเข้าถึงได้ตลอด กับอุโมงค์ตอนที่อยากให้ Claude Pro คุมเกม ย้ายแคมเปญไปมาได้ด้วย
**Export** และ **Import**

## เล่นฟรีโดยไม่ต้องมี API key

มีสามทาง ถ้าคุณจ่ายค่า Claude อยู่แล้ว ให้เริ่มจากทางที่สาม

> **ไม่ต้องแตะเทอร์มินัลเลยก็ได้** เปิดแอปทั้งที่ยังไม่ตั้งค่าอะไร แล้วมันจะเสนอลิงก์ให้เอง
> — **ขอคีย์ฟรีจาก Google Gemini**, **จาก Groq**, **ติดตั้ง Ollama** — พร้อมช่องให้วาง
> คีย์ได้ทันที เซิร์ฟเวอร์จะตรวจคีย์กับผู้ให้บริการก่อนเก็บ บอกให้รู้ถ้าถูกปฏิเสธ และเริ่ม
> ทำงานทันที ไม่ต้อง `setx` ไม่ต้องรีสตาร์ต
>
> ช่องเดียวกันนี้อยู่ใต้ปุ่มเลือก AI ในลิ้นชักแผ่นตัวละครด้วย เผื่อจะเพิ่มผู้ให้บริการ
> เจ้าอื่นทีหลัง

### Google Gemini — คีย์ฟรี ไม่ต้องใช้บัตรเครดิต

1. ไปที่ **aistudio.google.com/apikey** แล้วล็อกอินด้วยบัญชี Google
2. กด **Create API key** เท่านั้นเอง ไม่ต้องผูกบัตร ไม่ต้องตั้งค่าการเรียกเก็บเงิน
   คีย์จะขึ้นต้นด้วย `AIza`
3. วางคีย์ลงในแอปได้เลย (ง่ายสุด) หรือจะตั้งเป็นตัวแปรสภาพแวดล้อมก็ได้:

```bash
setx GEMINI_API_KEY "AIza-paste-yours-here"
```

**Gemini 2.0 Flash (free)** จะโผล่ในปุ่มเลือก AI พร้อมป้าย *free tier* และกลายเป็นค่า
เริ่มต้นเมื่อไม่ได้ตั้งคีย์ Claude แพลนฟรีจำกัดเป็นจำนวนครั้งต่อวันแทนที่จะเก็บเงิน —
พอสำหรับการเล่นปกติ และถ้าชนลิมิต เกมจะสลับไปใช้ตัวอื่นที่ตั้งค่าไว้ให้เอง

**Groq** ใช้วิธีเดียวกันและเร็วมาก ขอคีย์ฟรีที่ **console.groq.com/keys** ไม่ต้องใช้บัตร
แล้วสั่ง `setx GROQ_API_KEY "gsk_..."`

สองตัวนี้ง่ายกว่าทุกอย่างที่เหลือ ถ้าแค่อยากเล่นคืนนี้ ไปขอคีย์ Gemini

### Ollama — ฟรีตลอดไป ทำงานออฟไลน์ ไม่ต้องมีบัญชี

**Ollama** รันโมเดลบนเครื่องคุณเอง ไม่มีคีย์ ไม่มีบัญชี ไม่มีโทเคนให้หมด และใช้ได้แม้
ไม่มีอินเทอร์เน็ต

1. ติดตั้งจาก **ollama.com/download** (ตัวติดตั้ง Windows ปกติ)
2. ดึงโมเดลที่พอดีกับเครื่อง:

```bash
ollama pull llama3.2:3b
```

3. รีสตาร์ตเซิร์ฟเวอร์เกม **Llama 3.2 3B (local)** จะโผล่ในปุ่มเลือก AI พร้อมป้าย
   *on this PC* และแคมเปญใหม่จะใช้ตัวนี้อัตโนมัติเมื่อไม่มี API key

`qwen2.5:3b` เป็นอีกตัวเริ่มต้นและมักเขียนสำนวนดีกว่านิดหน่อย — ดึงมาทั้งคู่แล้วสลับ
ด้วยปุ่มเลือก AI ได้ เปลี่ยนรายชื่อโมเดลด้วย `OLLAMA_MODELS` และตั้ง `OLLAMA_HOST`
ถ้า Ollama รันอยู่อีกเครื่อง

**คาดหวังอะไรได้บนโน้ตบุ๊กธรรมดา** (แรม 8GB ไม่มีการ์ดจอแยก): โมเดล 3B ใช้เวลาเขียน
ราว 20–40 วินาทีต่อเทิร์น และ DM จะอ่อนกว่า Claude อย่างเห็นได้ชัด — บรรยายสั้นกว่า
NPC ตื้นกว่า และจำเรื่องที่เกิดเมื่อหลายฉากก่อนได้ไม่ค่อยแม่น โมเดลใหญ่กว่าเก่งกว่าแต่
กินแรมมากกว่า: ขนาด 7–8B ควรมีแรม 16GB จึงจะสบาย

ส่วนสำคัญยังเหมือนเดิมทุกกรณี: **ลูกเต๋าและแผ่นตัวละครยังรันด้วย Python** โมเดลอ่อน ๆ
จึงโกงการทอยหรือทำพลังชีวิตคุณเพี้ยนไม่ได้ ถ้าโมเดลเล็กลืมเรียกเครื่องมือทอยลูกเต๋าไป
เลย คุณจะเห็นทันที — ไม่มีป้ายลูกเต๋าโผล่ และแผ่นตัวละครไม่มีอะไรเปลี่ยน มันจะกลายเป็น
การเล่านิทานที่ไม่มีกลไก แทนที่จะแอบกุผลลัพธ์เงียบ ๆ

> โมเดลต้องรองรับการเรียกเครื่องมือ (tool calling) `llama3.2` และ `qwen2.5` รองรับ
> โมเดลเล็กหลายตัวไม่รองรับ — ตรวจก่อนเปลี่ยน

### มี Claude Pro อยู่แล้ว? ให้เว็บแอปใช้ซับสคริปชันของคุณ

ซับสคริปชัน Claude Pro หรือ Max ครอบคลุม claude.ai และ **Claude Code** มันไม่ใช่ API key
และไม่มีสิทธิ์ OAuth ใดที่เว็บแอปจะขอเพื่อใช้ซับสคริปชันของคนอื่นได้ — เกมนี้จึงล็อกอิน
ผู้เล่นด้วยบัญชี Claude ของแต่ละคนไม่ได้ สิ่งที่ทำได้คือสั่งงาน Claude Code ที่ติดตั้งอยู่
บนเครื่องที่รันเซิร์ฟเวอร์ ซึ่งเป็นการใช้งานตามปกติของสิ่งที่คุณจ่ายเงินอยู่แล้ว

ติดตั้ง Claude Code ล็อกอิน แล้วเพิ่ม Agent SDK:

```bash
pip install claude-agent-sdk
```

รีสตาร์ตเซิร์ฟเวอร์ **Claude Pro/Max (this machine)** จะโผล่ในรายการ AI ในลิ้นชักแผ่น
ตัวละคร และแคมเปญใหม่จะเริ่มด้วยตัวนี้ รายการนี้ตรวจด้วยว่า Claude Code ล็อกอินอยู่จริง
หรือไม่ ถ้ายังไม่ล็อกอินจะติดป้าย **sign in needed** — เพราะ "ติดตั้งแล้ว" กับ
"ล็อกอินแล้ว" เป็นคนละเรื่อง และถ้าไม่บอกตรงนี้ก็จะรู้ตอนเทิร์นพังไปแล้ว

ถ้ายังไม่ได้ล็อกอิน ปุ่ม **Sign in with Claude** อยู่ในแผงเดียวกัน มันจะรัน `auth login`
ของ Claude Code เองบนเครื่องนี้ แล้วแสดงลิงก์ที่มันพิมพ์ออกมา ซึ่งเป็นหน้าอนุญาตสิทธิ์
จริงของ Anthropic — เกมไม่เคยเห็นรหัสผ่านหรือโทเคนของคุณ ปกติขั้นตอนจะจบเองในเบราว์เซอร์
ที่มันเปิดให้ แล้วแถวนั้นจะเปลี่ยนเป็นสีเขียว ถ้า Anthropic แสดงรหัสมาแทน ให้วางรหัสลงช่อง

ปุ่มนั้นใช้ได้ **จากเครื่องที่รันเกมเท่านั้น** ผู้เล่นที่เข้ามาทางอุโมงค์จะได้ 403 และไม่เห็น
ลิงก์เลย เพราะใครก็ตามที่ทำขั้นตอนล็อกอินนี้จบ คือคนที่ตัดสินว่าบัญชี Claude ไหนจะจ่าย
ค่าทุกเทิร์นบนโต๊ะนี้ ไม่ต้องใช้คีย์ ไม่ต้องมีเครดิต — เทิร์นถูกคิดกับซับสคริปชัน และนับ
รวมในลิมิตการใช้งานเหมือนงาน Claude Code อื่น ๆ เมื่อชนลิมิต เทิร์นนั้นจะสลับไปใช้ AI
ตัวถัดไปที่ตั้งค่าไว้ เหมือนตอน API key หมดเครดิต

ทุกคนบนโต๊ะได้ใช้ร่วมกัน: เพื่อนที่เข้ามาทางอุโมงค์ก็ใช้ DM ของเจ้าบ้าน เหมือนกับแบ็กเอนด์
อื่นทุกตัว ลูกเต๋าไม่เปลี่ยน — Claude Code เรียก `roll_dice` และ `update_character` ผ่าน
เซิร์ฟเวอร์ MCP ในโปรเซส ซึ่งเรียก `game/rules.py` ตัวเดียวกับที่แบ็กเอนด์อื่นใช้

มีสองเรื่องที่ควรรู้ Claude Code มองไม่เห็นรูปที่ผู้เล่นแนบมา แคมเปญบนแบ็กเอนด์นี้จึงได้
แค่คำบรรยายภาพ ไม่ได้ตัวภาพ และแต่ละเทิร์นถูกส่งไปพร้อมเรื่องราวที่ผ่านมาซึ่งพับรวมอยู่
ในพรอมป์ แทนที่จะไปต่อเซสชันของ Claude Code — เพื่อให้มีบันทึกแคมเปญฉบับจริงเพียงชุดเดียว
คือชุดที่ถูก export และชุดที่ AI ตัวอื่นอ่านถ้ามารับช่วงต่อกลางแคมเปญ

ปรับแต่งได้ด้วย `CLAUDE_CODE_MODEL` (ค่าเริ่มต้น `claude-opus-5`), `CLAUDE_CODE_PATH`
ถ้า `claude` ไม่ได้อยู่ใน `PATH` และ `CLAUDE_CODE_TRANSCRIPT_TURNS` สำหรับจำนวนประวัติ
ที่ส่งไปด้วย (ค่าเริ่มต้น 40)

### หรือจะเล่นในเทอร์มินัล ภายใน Claude Code เลยก็ได้

เปิดเทอร์มินัลในโฟลเดอร์นี้ รัน `claude` แล้วพิมพ์:

```bash
/dm
```

คำสั่งนั้นโหลด `.claude/commands/dm.md` แล้วเซสชันนั้นจะกลายเป็น DM ของคุณ มันทอยลูกเต๋า
จริงและดูแลแผ่นตัวละครโดยเรียก `play.py` ซึ่งครอบ `game/rules.py` ตัวเดียวกับที่เว็บแอปใช้
— การรับประกันความซื่อสัตย์จึงเหมือนกันทุกประการ คุณจะเห็นทุกการทอย:

```
Stealth vs DC 14: 1d20+3 -> [14] +3 = 17
  -> SUCCESS against DC 14
```

ตัวละครเก็บอยู่ใน `saves/` และใช้ร่วมกับตัวเล่นผ่านเทอร์มินัล DM จะบันทึกสิ่งที่เกิดขึ้น
ด้วย `play.py note` และอ่านกลับด้วย `play.py recap` ในครั้งถัดไป แคมเปญจึงอยู่ข้ามรอบ
การเล่นได้

จะสั่งเครื่องมือชุดเดียวกันนี้เองโดยไม่ใช้ AI เลยก็ได้ ถ้าอยากเป็น DM เอง:

| คำสั่ง | ทำอะไร |
|---|---|
| `python play.py new "Vess" Elf Rogue` | สุ่มตัวละคร (`--lang th` สำหรับภาษาไทย) |
| `python play.py roll 1d20+3 --dc 14` | ทอยลูกเต๋า และบอกว่าผ่าน DC หรือไม่ |
| `python play.py update Vess --hp -4 --xp 25` | ใส่ความเสียหาย XP ทอง ไอเทม สถานะ |
| `python play.py sheet Vess` | แสดงแผ่นตัวละคร |
| `python play.py note Vess "..."` | บันทึกสิ่งที่เกิดขึ้น |
| `python play.py recap Vess` | อ่านบันทึกแคมเปญย้อนหลัง |

สิ่งที่เสียไปเมื่อเทียบกับเว็บแอป: ไม่มีหน้าจอในเบราว์เซอร์ ไม่มีมือถือ (เว้นแต่ใช้
Claude Code บนเว็บ) ไม่มีปาร์ตี้ — มีแค่ผู้เล่นคนเดียวนั่งโต๊ะกับ Claude สิ่งที่ได้คือ
ไม่ต้องติดตั้งอะไรเพิ่มนอกจาก Claude Code เอง ถ้าอยากได้เบราว์เซอร์ มือถือ และปาร์ตี้
บนซับสคริปชันเดียวกัน ให้ใช้แบ็กเอนด์ในหัวข้อก่อนหน้าแทน

## เมื่อโทเคนหมด

ลิ้นชักแผ่นตัวละครมีปุ่ม **Which AI runs the game** ซึ่งแสดง AI ทุกตัวที่เซิร์ฟเวอร์เข้าถึง
ได้ แตะตัวไหนก็ส่งมอบโต๊ะให้ตัวนั้น การสลับมีผลเฉพาะแคมเปญนั้น และเริ่มใช้ในเทิร์นถัดไป

ส่วนใหญ่คุณไม่ต้องใช้มันเลย ถ้า AI ที่คุมแคมเปญอยู่ตอบว่า "เครดิตหมด" "ถูกจำกัดอัตรา"
หรือ "คีย์ผิด" กลางเทิร์น ระบบจะลองเทิร์นนั้นใหม่กับ AI ตัวถัดไปที่ใช้ได้ — รวมถึงโมเดล
Ollama บนเครื่อง ซึ่งไม่มีวันหมด — แล้วขึ้นบรรทัดในฟีดว่า:

> *Claude Opus 5 ran out — GPT-4o mini has taken over the table.*

ไม่มีอะไรสูญหาย สิ่งที่ AI ตัวที่พังเขียนค้างไว้จะถูกทิ้งก่อนลองใหม่ คุณจึงไม่เจอย่อหน้า
ที่ครึ่งหนึ่งเป็นสำนวนหนึ่งและอีกครึ่งเป็นอีกสำนวน และแคมเปญจะอยู่กับ AI ตัวที่ทำงานได้จริง

คีย์ฟรีก็นับเป็นตัวสำรองด้วย — คีย์ Gemini หรือ Groq ไม่มีค่าใช้จ่ายและเป็นที่รองรับเวลา
ระบบสลับ ถ้าอยากได้โมเดลเสียเงินหลายตัวในยอดเงินก้อนเดียว ขอคีย์
[OpenRouter](https://openrouter.ai/keys):

```bash
setx OPENROUTER_API_KEY "sk-or-..."
```

รีสตาร์ตเซิร์ฟเวอร์แล้ว GPT-4o mini, Gemini Flash, DeepSeek และ Llama จะโผล่ในรายการ
เลือกโมเดลอื่นด้วย `OPENROUTER_MODELS`:

```bash
setx OPENROUTER_MODELS "openai/gpt-4o-mini,qwen/qwen-2.5-72b-instruct"
```

> **โมเดลต้องรองรับการเรียกเครื่องมือ** เพราะ DM ทอยลูกเต๋าผ่านเครื่องมือ โมเดลที่ไม่รองรับ
> จะต้องกุผลลัพธ์เอง ซึ่งเป็นสิ่งเดียวที่การออกแบบทั้งหมดนี้มีไว้เพื่อป้องกัน ค่าเริ่มต้น
> ทั้งสี่ตัวรองรับหมด — ถ้าจะเพิ่มตัวอื่น ตรวจที่หน้าโมเดลของ OpenRouter ก่อน

`DM_BACKEND` กำหนดว่าแคมเปญใหม่เริ่มด้วย AI ตัวไหน ส่วน `GEMINI_MODELS`, `GROQ_MODELS`,
`OPENROUTER_MODELS` และ `OLLAMA_MODELS` เปลี่ยนรายชื่อโมเดลของแต่ละผู้ให้บริการ ในตัวเล่น
ผ่านเทอร์มินัล `/ai` แสดงรายการทั้งหมด และ `/ai DeepSeek` ใช้สลับ

Claude เป็น DM ที่ดีกว่า — มันคุมฉากให้ต่อเนื่องตลอดแคมเปญยาว ๆ ได้ในแบบที่โมเดลถูกกว่า
และโมเดลบนเครื่องทำไม่ได้ ให้มองตัวอื่นเป็นสิ่งที่ทำให้เกมเดินต่อได้ตอนตีหนึ่งเมื่อยอดเงิน
เป็นศูนย์ ไม่ใช่ของทดแทนที่เท่าเทียมกัน

**หมายเหตุเรื่อง Claude Pro:** ซับสคริปชัน Claude Pro หรือ Max ครอบคลุม claude.ai และ
Claude Code ไม่ใช่ API ไม่มีวิธีที่ได้รับการสนับสนุนให้ชี้ *เซิร์ฟเวอร์* นี้ไปที่ซับสคริปชัน
Pro และอะไรก็ตามที่อ้างว่าทำได้ล้วนทำงานด้วยการปลอมเป็นเซสชันเบราว์เซอร์ ซึ่งผิดข้อกำหนด
ของ Anthropic และเสี่ยงพังหรือทำให้บัญชีถูกระงับ สิ่งที่ซับสคริปชันครอบคลุมจริงคือการเล่น
ผ่าน Claude Code ด้วย `/dm` ตามที่อธิบายไว้ข้างต้น

## คีย์ที่วางไว้เก็บอยู่ที่ไหน และใครตั้งได้บ้าง

คีย์ที่วางลงในแอปจะถูกเขียนลง `.keys.json` ข้าง ๆ ฐานข้อมูล เป็นข้อความธรรมดา ความเสี่ยง
เท่ากับตัวแปรสภาพแวดล้อม และถูก git-ignore ไว้ ตัวแปรสภาพแวดล้อมจริงมีลำดับความสำคัญ
เหนือคีย์ที่บันทึกไว้เสมอ `setx` จึงยังเขียนทับได้

การตั้งคีย์ถูกจำกัดไว้โดยตั้งใจ เพราะเป็นสิ่งเดียวในนี้ที่ใช้เงิน:

- **ตั้ง `APP_PASSWORD` ไว้** — ใครที่ใส่รหัสผ่านผ่านแล้วตั้งคีย์ได้ นี่คือวิธีตั้งจาก
  มือถือกับอินสแตนซ์ที่ดีพลอยไว้
- **ไม่ได้ตั้งรหัสผ่าน** — รับเฉพาะคำขอที่มาจากเครื่องที่รันเซิร์ฟเวอร์เท่านั้น อินสแตนซ์
  สาธารณะที่ไม่มีรหัสผ่านจะปฏิเสธการเปลี่ยนคีย์ทันทีและบอกเหตุผล
- **`ALLOW_KEY_SETUP=0`** — ปิดความสามารถนี้ทั้งหมด

คีย์ไม่เคยถูกส่งกลับไปยังเบราว์เซอร์ แอปรู้แค่ *ว่า* ผู้ให้บริการเจ้าไหนตั้งค่าไว้แล้วบ้าง
การลบคีย์จะลบทั้งจากไฟล์และจากโปรเซสที่กำลังรัน

## ล็อกให้แน่นหนา

เซิร์ฟเวอร์ถือ API key ของคุณอยู่ ใครเปิด URL ได้ก็ใช้เครดิตคุณได้ ตั้งรหัสผ่านแล้วทั้งแอป
จะอยู่หลังรหัสนั้น:

```bash
setx APP_PASSWORD "วลียาวๆ สักอัน"
```

ถ้าใช้เฉพาะบนเครื่องตัวเองจะไม่ตั้งก็ได้ ส่วน `MAX_TURNS_PER_MIN` (ค่าเริ่มต้น 12) จำกัด
ว่าแคมเปญเดียวเผาเทิร์นได้เร็วแค่ไหน — ควรคงไว้ โดยเฉพาะเมื่อแคมเปญสลับไปใช้บัญชีที่สอง
ได้เองแล้ว

## เล่นคนเดียวหรือเป็นปาร์ตี้ก็ได้

ทุกแคมเปญมีรหัสแชร์ 6 ตัวอักษร การเล่นคนเดียวเป็นเรื่องปกติ ไม่ต้องตั้งอะไรเพิ่ม

ถ้าจะชวนคนเข้ามา แตะ **Share code** ในลิ้นชักแผ่นตัวละคร แล้วส่งลิงก์ให้เขา เขาเปิดลิงก์
เลือกชื่อ เผ่าพันธุ์ และคลาส แล้วก็อยู่ในฉากเดียวกันทันที รับได้สูงสุด 6 ตัวละครต่อแคมเปญ

การเล่นเป็นแบบอิสระเหมือนโต๊ะจริง — ใครจะทำอะไรตอนไหนก็ได้ และ DM เห็นว่าใครทำอะไร
มันจะไม่บังคับให้คุณรอลำดับ initiative

**ตัวละครเดียวกันบนสองอุปกรณ์:** เปิดแอปบนมือถือ ใส่รหัสแคมเปญ แล้วเลือกตัวละครเดิมของคุณ
จากรายการแทนที่จะสร้างใหม่ ตัวละครจะย้ายมาที่อุปกรณ์นั้น

**การเข้าร่วมทีหลังเป็นเรื่องปกติ** แคมเปญที่เล่นมาหลายชั่วโมงรับผู้เล่นใหม่ได้เหมือน
แคมเปญเปล่า ๆ เขาจะได้เรื่องราวทั้งหมดเล่นย้อนเข้าฟีดของเขาระหว่างเข้ามา และ DM จะถูกบอก
ณ จุดนั้นในบันทึกว่ามีคนมาถึงแล้ว มันจึงเขียนคนใหม่เข้าไปในฉาก แทนที่จะพบคนแปลกหน้าอยู่
ในปาร์ตี้อยู่แล้ว

### บันทึกถึง DM (Notes for the DM)

ในลิ้นชักแผ่นตัวละคร ใต้หัวข้อ **Notes for the DM** ผู้เล่นแต่ละคนเก็บรายละเอียดประจำตัว
ของตัวละครตัวเองไว้ — โทนที่อยากได้ ภูมิหลังที่ตัดสินใจไว้แล้ว ปมที่อยากให้หยิบมาเล่นต่อ
หรือเรื่องที่อยากให้เกมเลี่ยง:

> เวสส์กลัวไฟมาตั้งแต่หมู่บ้านของเธอถูกเผา และกำลังตามหาพี่ชายที่ทิ้งเธอไป
> ฉันอยากไล่ล่าปริศนามากกว่าจะรบในสงคราม

ข้อความนี้จะติดไปกับทุกเทิร์นของตัวละคร *นั้น* เท่านั้น — ความชอบของผู้เล่นคนอื่นจะไม่ไป
กระซิบข้าง DM ในเทิร์นที่ไม่ใช่ของเขา มีแค่คุณที่แก้ของคุณได้ คนอื่นบนโต๊ะไม่ได้รับ และมัน
ติดไปกับ **Export** ด้วย

ความยาวถูกจำกัดที่ 600 ตัวอักษรโดยตั้งใจ เพราะทุกข้อความถูกส่งซ้ำทุกเทิร์น ถ้ามีคำนำของ
ผู้เล่นหกคน ฉากจริงจะถูกดันลงไปอยู่ท้ายพรอมป์ ให้เขียนสิ่งที่ควรเป็นจริงเสมอ ไม่ใช่สิ่งที่
คุณกำลังทำอยู่ในเทิร์นนี้

## ภาษาไทย

แตะ **ไทย** ในตัวสลับภาษา (อยู่ที่หน้าล็อกอิน ท้ายหน้าล็อบบี้ หรือในลิ้นชักแผ่นตัวละคร)
แล้วทุกอย่างจะตามมา:

- DM เล่าเรื่อง สวมบทบาท NPC และเขียนเหตุผลการทอยลูกเต๋าเป็นภาษาไทย
- หน้าจอทั้งหมด — ปุ่ม ป้ายกำกับ เผ่าพันธุ์ คลาส ชื่อค่าความสามารถ แผ่นตัวละคร
- ของติดตัวเริ่มต้นถูกเขียนลงแผ่นตัวละครเป็นภาษาไทย (ดาบสั้น เกราะหนัง คบไฟ) แคมเปญไทย
  จึงอ่านเป็นไทยตั้งแต่เทิร์นแรก
- การจัดตัวอักษรแบบไทย: ฟอนต์ทั้งชุดเปลี่ยนเป็น Sarabun / Noto Sans Thai พร้อมเพิ่ม
  ระยะบรรทัด เพราะวรรณยุกต์และสระวางซ้อนกันทั้งบนและล่างเส้นฐาน และจะชนกันที่ระยะบรรทัด
  แบบละติน ส่วนตัวพิมพ์ใหญ่และการถ่างตัวอักษรถูกยกเลิก — ทั้งสองอย่างเป็นกลไกของอักษร
  ละตินล้วน ๆ ที่ทำให้ภาษาไทยเสียรูป

ภาษาที่คุณเลือกตอนสร้างแคมเปญคือภาษาที่ DM ของแคมเปญนั้นใช้เล่าเรื่อง และจะติดอยู่กับ
แคมเปญนั้น ส่วนภาษา *หน้าจอ* ของคุณเป็นค่าตั้งแยกต่างหากของแต่ละอุปกรณ์ — ผู้เล่นไทยกับ
ผู้เล่นอังกฤษจึงนั่งโต๊ะเดียวกันได้ แต่ละคนอ่านปุ่มเป็นภาษาของตัวเอง ขณะที่ DM เล่าให้
ทั้งคู่ฟังเป็นภาษาไทย

เบื้องหลัง เผ่าพันธุ์ คลาส และค่าความสามารถถูกเก็บเป็นภาษาอังกฤษแล้วแปลตอนแสดงผล ซึ่งเป็น
สิ่งที่ทำให้เรื่องข้างต้นเป็นไปได้ ส่วนข้อความที่คนเขียนเอง — ชื่อตัวละคร ไอเทมที่ DM คิดขึ้น
ตัวเรื่องเอง — ถูกเก็บตามที่พิมพ์ ในภาษาที่เขียนมา

การสลับภาษากลางเกมจะวาดหน้าจอใหม่ทันที ส่วนเนื้อเรื่องที่อยู่บนจอแล้วยังคงภาษาเดิมที่มัน
ถูกเขียน เพราะมันคือบันทึกของสิ่งที่เกิดขึ้นไปแล้ว

## รูปภาพ

มีสามวิธีเอารูปเข้าแคมเปญ ทั้งหมดอยู่ในลิ้นชักแผ่นตัวละครหรือที่ปุ่มคลิปหนีบข้างช่องพิมพ์:

- **อัปโหลด** ไฟล์ หรือถ่ายรูปจากมือถือ
- **จากลิงก์** — วางที่อยู่รูป แล้วเซิร์ฟเวอร์จะไปดึงมาให้
- **ให้วาด** — ให้ AI สร้างภาพเหมือนตัวละคร หรือวาดฉากปัจจุบัน

ยังมีวิธีที่สี่ซึ่งไม่ต้องมีใครสั่ง: ถ้าตั้งค่า AI ที่วาดรูปได้ไว้ DM จะวาดภาพประกอบฉากเอง
ดูหัวข้อ **เมื่อ DM วาดภาพประกอบเอง** ด้านล่าง

**ภาพเหมือน (Portrait)** จะขึ้นบนแผ่นตัวละครของคุณ และเป็นรูปหน้าเล็ก ๆ ข้างชื่อคุณในแถบ
ปาร์ตี้ ส่วน **ไฟล์แนบ** จะเข้าไปในฟีดให้ทุกคนบนโต๊ะเห็น และ DM ก็เห็นด้วย — "นี่แผนที่
ที่ผมเจอ คิดว่ามันคืออะไร?" — ใช้ได้กับผู้ให้บริการที่รองรับการมองภาพ (Claude, Gemini,
Groq ส่วนโมเดล Ollama บนเครื่องมักทำไม่ได้ และจะถอยไปเป็นแค่รู้ว่ามีการโชว์รูปโดยไม่เห็นรูป)

รูปที่แนบจะถูกส่งไปในเทิร์นที่มันปรากฏ แล้วหลุดออกจากประวัติ ถ้าปล่อยไว้ มันจะถูกส่งซ้ำ
ทุกเทิร์นและทำให้ค่าใช้จ่ายทวีขึ้นเงียบ ๆ

> **การสร้างภาพต้องเปิดการเรียกเก็บเงิน** แพลนฟรีของ Google ครอบคลุมข้อความแต่ไม่ครอบคลุม
> การวาด — โมเดลรูปจะตอบ HTTP 429 กับคีย์ฟรี ปุ่ม **Draw it** และ **Illustrate this
> scene** จะบอกตรง ๆ แทนที่จะเงียบไป ส่วนอย่างอื่น — อัปโหลด ลิงก์ ภาพเหมือน การมองภาพ —
> ใช้ได้บนแพลนฟรี

### เมื่อ DM วาดภาพประกอบเอง

เมื่อตั้งค่า AI ที่วาดรูปได้ไว้ DM จะได้เครื่องมือชิ้นที่สี่ชื่อ `draw_scene` และจะใช้มัน
ในจังหวะที่ควรมีภาพ — การเห็นสถานที่ใหม่ครั้งแรก สัตว์ประหลาดที่เพิ่งเผยตัว ตอนจบของการ
ต่อสู้ที่หนักหนา ไม่ต้องมีใครกดอะไร รูปจะมาถึงในฟีดหลังคำบรรยายเล็กน้อย พร้อมป้ายกำกับ
*The DM illustrates the scene*

มีสองอย่างที่กันไม่ให้ค่าใช้จ่ายบานปลาย

**การจำกัดอยู่ในโค้ด ไม่ใช่ในพรอมป์** เราขอให้ DM ใช้อย่างประหยัด แต่การขอไม่ใช่การรับประกัน
— โมเดลช่างพูดจะวาดทุกย่อหน้าแล้วเก็บเงินคุณ ดังนั้นแต่ละแคมเปญจึงถือช่องวาดภาพไว้ช่องเดียว
ซึ่งเติมกลับทุก ๆ `DM_ART_EVERY_TURNS` เทิร์นของผู้เล่น (ค่าเริ่มต้น 6) และต้องจองใน SQLite
ก่อนวาดจริง เมื่อช่องว่างหมด เครื่องมือจะตอบว่า *ยังไม่ใช่ตอนนี้* DM ก็เล่าเรื่องต่อไป และ
โต๊ะไม่เคยเห็นการปฏิเสธนั้น รูปแรกของแคมเปญได้ฟรีเสมอ — ซึ่งมักเป็นฉากเปิด ที่มีเหตุผลควร
วาดมากกว่าฉากไหน ๆ หลังจากนั้น

```bash
setx DM_ART_EVERY_TURNS 12      # ให้นานๆ ครั้ง
setx DM_ART_EVERY_TURNS 999     # เท่ากับปิดในทางปฏิบัติ
```

ถ้าไม่ตั้งค่าผู้ให้บริการที่วาดรูปเลย เครื่องมือนี้จะหายไปทั้งชิ้น ซึ่งเป็นสวิตช์ปิดของจริง

**มันไม่เคยทำให้เทิร์นค้าง** การสร้างรูปหนึ่งใบใช้เวลาเกือบหนึ่งนาที ส่วนวงจรเทิร์นคือสิ่งที่
สตรีมคำบรรยายไปยังทุกเบราว์เซอร์บนโต๊ะ ถ้าไปรอรูปตรงนั้น ฉากจะค้างกลางประโยคสำหรับทุกคน
การวาดจึงแยกไปทำต่างหากและมาลงฟีดเมื่อเสร็จ เหมือนการอัปโหลด ทุกรูปแบบของความล้มเหลว —
ไม่มีผู้วาด โดน 429 บนคีย์ฟรี โมเดลคืนข้อความแทนรูป หรือแคมเปญชนเพดาน 60 รูปแล้ว — จะทิ้ง
เทิร์นไว้เหมือนเดิมทุกประการ พร้อมบรรทัดหนึ่งในล็อกของเซิร์ฟเวอร์ และโต๊ะที่ไม่เคยรู้ว่า
กำลังจะมีรูปมา

ภาพของ DM ถูกเก็บ จำกัด export และ import เหมือนรูปอื่นทุกใบ: ที่เก็บไฟล์เดียวกันคือ
`media/<campaign>/<sha256>.<ext>` เพดาน `MEDIA_MAX_PER_CAMPAIGN` เดียวกัน และเดินทางเข้า
ไฟล์ `.zip` แบบเดียวกัน

### เกิดอะไรขึ้นกับไฟล์ที่คุณอัปโหลด

รูปทุกใบถูกถอดรหัสด้วย Pillow แทนที่จะเชื่อนามสกุลไฟล์ แล้วเข้ารหัสใหม่จากพิกเซลดิบ
นั่นทำลาย **EXIF ทั้งหมด รวมถึงพิกัด GPS** และอะไรก็ตามที่ซ่อนอยู่ในตัวคอนเทนเนอร์ ส่วน SVG
ถูกปฏิเสธทันที เพราะมันคือภาชนะใส่สคริปต์ ไม่ใช่รูปภาพ ไฟล์ถูกเก็บแบบอ้างอิงตามเนื้อหาไว้ที่
`media/<campaign>/<sha256>.<ext>` จำกัดขาเข้า 8MB ขนาด 2048px (512px สำหรับภาพเหมือน) และ
60 รูปต่อแคมเปญ

การวางลิงก์เป็นประตูที่เสี่ยงกว่า เซิร์ฟเวอร์จึงปฏิเสธที่อยู่ใดก็ตามที่ชี้ไปยัง localhost
ช่วง LAN ส่วนตัว หรือปลายทาง metadata ของคลาวด์ — และตรวจซ้ำทุกครั้งที่มีการ redirect
เพราะ URL สาธารณะเด้งไปหา URL ส่วนตัวได้

รูปถูกให้บริการผ่าน `/api/campaigns/{id}/media/{id}` หลังการตรวจสมาชิกเดียวกับทุกอย่าง
ไม่เคยเสิร์ฟจากโฟลเดอร์ static **ใครก็ตามที่มีรหัสแคมเปญจะเห็นรูปเหล่านั้น** — ควรจำไว้
ก่อนอัปโหลดรูปของคนจริง

แคมเปญที่มีรูปจะ export ออกมาเป็น **`.zip`** (campaign.json บวกไฟล์) แทน JSON เปล่า ๆ
ส่วนการ import รับได้ทั้งสองแบบ — และผ่าน **…or an unzipped folder** ยังรับโฟลเดอร์ที่คุณ
แตกไฟล์ไว้แล้วได้ด้วย: ชี้ไปที่ไดเรกทอรีที่มี `campaign.json` กับโฟลเดอร์ `media/` ของมัน
ไม่ว่าจะเลือกแบบไหน เนื้อหาข้างในเป็นตัวตัดสินว่าจะอ่านอย่างไร ไม่ใช่ชื่อไฟล์ ไฟล์ export
ที่ถูกเปลี่ยนชื่อจึง import ได้เหมือนเดิม

## ย้ายแคมเปญที่คุณเล่นอยู่แล้วเข้ามา

ถ้าคุณเล่นเกมนี้ด้วยมืออยู่ก่อนแล้ว บันทึกและภาพย้ายตามมาได้ เปิดลิ้นชักแผ่นตัวละคร หา
**Campaign library** แล้วชี้ **Import a folder of your own material** ไปที่โฟลเดอร์ที่คุณ
เก็บของไว้ มันจะจัดการแยกแยะเอง:

- **รูปภาพ** (`.png`, `.jpg`, `.webp`, `.gif`) จะได้คำบรรยายจากชื่อไฟล์ —
  `NPC_Aria_Venn.png` กลายเป็น *Aria Venn* — และจัดชั้นตามโฟลเดอร์ที่มันอยู่:
  `NPC/` กับ `Characters/` กลายเป็น **Characters**, `Place/` กับ `Scenes/` กลายเป็น
  **Scenes**, `Maps/` กลายเป็น **Maps** ส่วนที่วางลอย ๆ กลายเป็นเอกสารแจก อ่านเฉพาะชื่อ
  โฟลเดอร์เท่านั้น ไม่เคยอ่านชื่อไฟล์: *Kentuckai_Father.png* บอกว่าเป็นใคร ไม่ได้บอกว่า
  เป็นรูปประเภทไหน สูงสุด 60 รูปต่อแคมเปญ
- **เอกสาร** (`.md`, `.txt`, `.html`) กลายเป็นบันทึกที่ DM ค้นได้ สูงสุด 40 ไฟล์ ไฟล์ละ 4MB
- อย่างอื่นถูกข้าม และจำนวนที่ข้ามไปจะถูกรายงาน ไม่ใช่เงียบหายไปเฉย ๆ

เอกสารเหล่านี้ *ไม่ได้* ถูกแปะลงพรอมป์ — แผ่นตัวละครใบเดียวอาจหนักถึง 100KB และถ้าเอา
ทั้งแคมเปญใส่เข้าไปก็จะเบียดเรื่องราวจนหมด แทนที่จะทำอย่างนั้น DM ได้เครื่องมือชิ้นที่สาม
ชื่อ `search_lore` พร้อมรายชื่อเอกสารที่มันเข้าถึงได้ เมื่อผู้เล่นเอ่ยชื่อใครที่มันไม่รู้จัก
มันจะไปค้นแล้วอ่านข้อความตอนนั้นกลับมา คุณเห็นตอนที่มันทำด้วย: ฟีดจะขึ้นว่า
*checked the notes for "…"* เหมือนตอนที่แสดงการทอยลูกเต๋า

การค้นใช้การเทียบสตริงย่อยตรง ๆ แทนการแยกคำ โดยตั้งใจ — เพราะ **ภาษาไทยเขียนติดกันโดย
ไม่เว้นวรรคระหว่างคำ** อะไรก็ตามที่ตัดคำด้วยช่องว่างจะหาอะไรในเอกสารไทยไม่เจอเลย การค้นหา
จึงทำงานเหมือนกันในทั้งสองภาษาที่เกมนี้พูด

หน้า HTML แบบมีทุกอย่างในตัวเก็บเนื้อหาไว้ใน `<script>` ระบบจึงอ่านส่วนนั้นด้วย ส่วนรูป
base64 ที่ฝังอยู่จะถูกตัดทิ้งก่อน เพราะมันกินพื้นที่เกือบทั้งไฟล์แต่ไม่มีความหมายอะไรเลย
เอกสารเดินทางไปกับ **Export** และ **Import** แคมเปญจึงย้ายได้ทั้งก้อน

ลบเอกสารเมื่อไรก็ได้จากแผงเดียวกัน

## มันทำงานอย่างไร

DM มีเครื่องมือสองชิ้นที่ทำงานในทุกแคมเปญ และทั้งคู่รันบนเครื่อง:

- **`roll_dice`** — โมเดลไม่มีวันบอกผลลัพธ์ที่มันไม่ได้ทอย มันต้องประกาศค่า DC ออกมาก่อน
  แล้วตัวเลขจึงมาจาก RNG ของ Python มันจึงแอบตัดสินว่าคุณสำเร็จไม่ได้ ทุกการทอยแสดงในฟีด:
  `Vess: Stealth vs DC 14 · 1d20+3 → [7]+3 = 10`
- **`roll_dice` พร้อมทักษะจริง** — ตัวละครแต่ละตัวถือความชำนาญของตัวเองไว้ และสถานะปาร์ตี้
  ส่งค่ารวมที่คำนวณเสร็จแล้วของทุกทักษะที่เขาชำนาญให้ DM เมื่อก่อนมันถูกขอเป็นร้อยแก้ว
  ให้จำว่า "+2 ความชำนาญที่เลเวล 1-4" แล้วเลือกตัวปรับเอง ซึ่งทำให้ทุกการตรวจแค่ดูสมเหตุ
  สมผล ไม่ใช่ถูกต้อง
- **`update_character`** — ความเสียหาย การรักษา XP ทอง ไอเทม และสถานะทั้งหมด ผ่านแผ่น
  ตัวละครในโค้ด โดยระบุชื่อตัวละครเจาะจง ผลลัพธ์ถูกป้อนกลับให้โมเดล มันจึงเพี้ยนจากพลัง
  ชีวิตจริงของคุณไม่ได้ การเลื่อนเลเวลจะทอยลูกเต๋าพลังชีวิตใหม่

อีกสองชิ้นจะโผล่ก็ต่อเมื่อมีอะไรรองรับอยู่จริง — เครื่องมือที่ไม่มีอะไรอยู่ข้างหลังแย่กว่า
การไม่มีเครื่องมือเลย เพราะโมเดลจะเอื้อมไปหยิบมันอยู่ดี:

- **`search_lore`** เมื่อแคมเปญมีเอกสารในคลัง ดูหัวข้อ **ย้ายแคมเปญที่คุณเล่นอยู่แล้ว
  เข้ามา** ด้านบน
- **`draw_scene`** เมื่อตั้งค่า AI ที่วาดรูปได้ ดูหัวข้อ **เมื่อ DM วาดภาพประกอบเอง**
  ด้านบน

ทุกอย่างที่เกิดขึ้นถูกต่อท้ายลงบันทึกเหตุการณ์พร้อมหมายเลขลำดับ และเบราว์เซอร์จำหมายเลข
ล่าสุดที่เห็น เมื่อมือถือคุณหลับ เปลี่ยนเครือข่าย หรือคุณปิดแท็บ มันจะเชื่อมต่อใหม่และเล่น
ซ้ำเฉพาะส่วนที่พลาดไป ฉากจึงไม่มีวันหาย

```
game/rules.py    ลูกเต๋า ค่าความสามารถ การสร้างตัวละคร   (ไม่มี I/O)
game/dm.py       system prompt เครื่องมือ และวงจรเทิร์นแบบ async
game/store.py    SQLite: แคมเปญ ตัวละคร บันทึกเหตุการณ์
game/i18n.py     ข้อความฝั่งเซิร์ฟเวอร์: ของติดตัว คำสั่งภาษาให้ DM, CLI
game/media.py    ตรวจรูป ลบ EXIF ป้องกัน URL อันตราย และที่เก็บไฟล์
game/providers.py  แบ็กเอนด์ AI การแปลงรูปแบบ และการสลับเมื่อพัง
server.py        FastAPI: การยืนยันตัวตน แคมเปญ สตรีม SSE การกระทำ
static/i18n.js   ข้อความหน้าจอฝั่งเบราว์เซอร์
static/          ส่วนที่เหลือของหน้าจอ — ไม่มีขั้นตอน build
dnd.py           ตัวเล่นผ่านเทอร์มินัล ใช้ DM เดียวกัน
tests/           pytest ขับด้วย DM จำลอง — ไม่ต้องมี API key ไม่เรียกโมเดล
```

## รันเทสต์

```bash
pip install -r requirements-dev.txt
python -m pytest
```

เทสต์ไม่ต้องใช้ API key และไม่เคยไปถึงโมเดลจริง: แบ็กเอนด์จำลองทำหน้าที่แทน AI และบันทึก
ว่ามันได้รับอะไรมาบ้าง ซึ่งเป็นวิธีที่ทำให้เทสต์ยืนยันได้ว่าบันทึกของผู้เล่นและสถานะปาร์ตี้
ที่ถูกต้องไปถึงพรอมป์จริง ๆ ไม่ใช่แค่ถูกบันทึกไว้ที่ไหนสักแห่ง

การเปลี่ยนแปลงบนแผ่นตัวละครเดินทางเป็นข้อมูลมีโครงสร้าง (`{"t": "hp", "from": 8, "to": 5}`)
แทนที่จะเป็นประโยคภาษาอังกฤษสำเร็จรูป แต่ละเบราว์เซอร์จึงแสดงผลเป็นภาษาของตัวเองได้

แบ็กเอนด์ทุกตัวในชุดเทสต์เป็นตัวจำลอง — DM ที่พูดตามบทที่เทสต์เขียนไว้เป๊ะ ๆ และนักวาดที่
คืน PNG ขนาดสี่พิกเซลกลับมา เทสต์จึงไม่ต้องใช้คีย์ ไม่เสียเงิน และให้คำตอบเดียวกันทั้งบน
เครื่องที่มีคีย์และเครื่องที่ไม่มี มันรันกับฐานข้อมูลและโฟลเดอร์สื่อชั่วคราว ไม่เคยแตะ
`campaign.db` ของคุณ

## ปรับแต่ง

- **`SYSTEM` ใน `game/dm.py`** — น้ำเสียง จังหวะ และกฎประจำบ้านของ DM อยากได้แนวสยองขวัญ
  หม่นมืด หรือแนวตลก หรือ DC ที่โหดกว่านี้? สตริงนี้คือบุคลิกทั้งหมดของมัน
- **`CLASSES` / `RACES` ใน `game/rules.py`** — เพิ่มของคุณเองได้ พร้อมลูกเต๋าพลังชีวิต
  และของติดตัว
- **การเพิ่มภาษา** — สามที่: `LANGUAGES`, `NARRATION_INSTRUCTION`, `GEAR`, `NAMES` และ
  `CLI` ใน `game/i18n.py`; บล็อกหนึ่งใน `STRINGS` ของ `static/i18n.js`; และบล็อกฟอนต์กับ
  ระยะบรรทัด `:root[data-lang="xx"]` ใน `static/style.css` ถ้าอักษรนั้นต้องการ ไม่มีส่วน
  อื่นของระบบที่รู้จักเรื่องภาษาเลย
- **`output_config={"effort": ...}` ใน `game/providers.py`** — `"low"` ให้เทิร์นของ Claude
  เร็วและถูกลง `"high"` ให้ DM คมขึ้น
- **การเพิ่มผู้ให้บริการ AI** — สืบทอด `Backend` ใน `game/providers.py` โดยเขียน
  `available()` และ `stream()` ที่ yield ข้อความทีละส่วนแล้วตามด้วยข้อความหนึ่งชุดในรูปแบบ
  block ของ Anthropic จากนั้นเพิ่มลงใน `_build()` ประวัติแคมเปญถูกเก็บในรูปแบบเดียวนั้น
  ส่วนอื่นจึงไม่ต้องรู้อะไรเพิ่ม

## ค่าใช้จ่าย

เริ่มจากตัวเลือกฟรีก่อน: แพลนฟรีของ **Gemini** และ **Groq** ไม่มีค่าใช้จ่าย (จำกัดต่อวัน)
ส่วน **Ollama** ไม่มีค่าใช้จ่ายเลยตลอดไป ถ้าเสียเงิน คร่าว ๆ ราวหนึ่งถึงสองเซนต์ต่อเทิร์น
ที่ราคาของ Opus 5 ระบบแคช system prompt ไว้ และประวัติแคมเปญยาวขึ้นเรื่อย ๆ ตลอดการเล่น
แคมเปญที่เล่นหลายชั่วโมงจึงตกราวไม่กี่ดอลลาร์ การสลับแคมเปญไปใช้ Claude Sonnet 5 หรือ
โมเดลใน OpenRouter ช่วยลดตรงนี้ได้มาก — ปุ่มเลือก AI จึงเป็นเครื่องมือคุมค่าใช้จ่ายพอ ๆ
กับเป็นตัวสำรอง

## ตัวเล่นผ่านเทอร์มินัล

```bash
python dnd.py
```

เล่นคนเดียวเท่านั้น บันทึกไว้ที่ `saves/<name>.json` มีคำสั่ง `/sheet`, `/roll`, `/save`,
`/recap` และ `/quit` มันจะถามภาษาก่อนแล้วทำงานเป็นภาษานั้นทั้งหมด — คำถาม แผ่นตัวละคร
ข้อความช่วยเหลือ ครบทุกส่วน ใช้ DM เดียวกัน ลูกเต๋าเดียวกัน กฎเดียวกันกับเว็บแอป
